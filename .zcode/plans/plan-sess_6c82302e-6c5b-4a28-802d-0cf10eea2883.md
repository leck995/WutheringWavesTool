## 目标

在 `AccountUpdateView` 点击「获取」后：弹出 WebView 完成极验滑块 → 校验通过后调用库街区 H5 发码接口 → 用户填写短信码后走现有 `loginBySMS` 登录。

---

## 现状与差异

| 项目 | 当前工程 | demo (`javafx-kuro-login`) |
|------|----------|---------------------------|
| 获取按钮 | 直接弹手动说明 `showSmsFailDialog()` | 打开 WebView 极验 |
| 发码 API | `sdkapi.../getPhoneCode.lg`（常 41000） | `api.kurobbs.com/user/getSmsCodeForH5` + `geeTestData` |
| WebView | **无** `javafx-web` | 有 |
| 登录 | 已有 `LoginUserTask` → `sdkLogin` | 同类 `sdkLogin`（可复用，无需改登录主流程） |

结论：按 demo 的 **H5 发码 + GeeTest** 路径替换「获取验证码」，登录沿用现有逻辑。

---

## 实现方案

### 1. 依赖与模块

- `pom.xml`：增加 `javafx-web`（版本 `${javafx.version}` = 25，与现有 controls/fxml 一致）
- `module-info.java`：`requires javafx.web;`

### 2. 移植极验资源与桥接

从 demo 复制并改包名：

| 文件 | 目标位置 |
|------|----------|
| `geetest.html` | `src/main/resources/web/geetest.html`（captchaId 保持 `ec4aa4174277d822d73f2442a165a2cd`） |
| `GeetestBridge` | `com.kuro.kujiequ.captcha.GeetestBridge` |

桥接职责不变：`window.javaBridge` 的 `onReady / onSuccess / onError / onClose`，回调切回 FX 线程。

### 3. 极验弹窗组件（封装 WebView 生命周期）

新增 `com.kuro.kujiequ.captcha.GeetestCaptchaDialog`（或 `cn.tealc...ui.kujiequ.account` 下，二选一；推荐放 `com.kuro.kujiequ.captcha` 便于复用）：

- 独立 **模态 Stage**（与 demo 一致；比塞进 `JFXDialog` 更稳，滑块不易被裁切/遮挡）
- 加载 `/web/geetest.html?t=时间戳`
- `SUCCEEDED` 后注入 bridge，`syncReadyToJava` + 短轮询 `isCaptchaReady`，再 `showCaptcha()`
- 成功：回调 `Consumer<String> onSuccess(geeTestJson)` 并关闭
- 失败/关闭滑块/关窗：回调失败或取消
- 失败可 `resetCaptcha()` 供重试（发码失败时）

### 4. 重写发码 Task

改造 `SendSmsTask`（或新建 `SendSmsWithGeetestTask` 并替换调用点）：

- URL：`https://api.kurobbs.com/user/getSmsCodeForH5`（可写入 `ApiConfig`）
- Body：`mobile` + `geeTestData`（极验 JSON 字符串）
- Headers：`source=h5`、`devcode`（32 位随机）、`version=3.1.3`、Kuro iOS UA（与 demo 一致）
- 构造：`SendSmsTask(String phone, String geeTestJson)`
- 成功判定：`success==true` 或 `code==0/200` → 返回 `ResponseBody` code 200
- 删除/停用旧的 `sdkapi getPhoneCode.lg` 路径（该路径本身依赖另一套 captcha，与本次 demo 不一致）

`devCode` 仅用于发码请求，**不必**与登录 `did` 绑定（demo 也是分开的）。

### 5. 串联 `AccountUpdateView` / ViewModel

**`AccountUpdateView.sendLoginCode`：**

1. 校验手机号 `^1[3-9]\d{9}$`
2. 打开 `GeetestCaptchaDialog`
3. `onSuccess` → `viewModel.sendSMS(geeTestJson)`
4. 可选：极验/发码彻底失败时仍提供 `showSmsFailDialog()` 作为人工兜底

**`AccountUpdateViewModel.sendSMS`：**

```text
sendSMS(String geeTestJson)
  → new SendSmsTask(phone, geeTestJson)
  → 200: toast「验证码发送成功」+ 启动 60s 冷却
  → 其他: toast 错误信息
```

去掉旧的 `41000 → callback` 分支（改由 WebView 完成校验）。

**FXML 小改：**

- 给「获取」按钮加 `fx:id="getCodeBtn"`，便于冷却文案（`60 秒后重试`）与 disable 绑定

**登录路径：**

- `loginBySMS` / `LoginUserTask` **保持不动**（验证码登录已可用）

### 6. 用户流程（整合后）

```text
输入手机号 → 点「获取」
  → Stage + WebView 极验
  → onSuccess(geeTestJson)
  → POST getSmsCodeForH5
  → 成功：关闭极验窗 + 60s 冷却 + toast
输入短信码 → 点「登录」
  → LoginUserTask(sdkLogin) → GameRoleSeekTask → 入库（现有逻辑）
```

## 风险与注意

- WebView 需能访问极验 CDN（`static.geetest.com` / `static.geevisit.com`）
- JavaFX 25 与 JDK 主版本需匹配（项目已用 javafx 25）
- 仅加载本地 `geetest.html`，不把任意远程页挂 `javaBridge`
- 嵌套在现有账号对话框之上再开 Stage 是正常模态层叠，关闭极验不影响账号对话框

## 验收

1. 添加账号 → 验证码登录页 → 填合法手机号 → 点「获取」弹出滑块
2. 完成滑块后收到短信，toast 成功，「获取」进入冷却
3. 填 6 位码登录成功并写入账号列表
4. 取消/关闭滑块不发短信；发码失败可提示并允许重试
5. Token 手动添加路径不受影响
