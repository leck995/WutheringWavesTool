声骸测评机制说明

leck大约 4 分钟

重要

助手的声骸测评不会提供评分。精确的评分只会助长 PVP 以及消耗玩家养成的热情，声骸测评存在的意义在于提供一个声骸毕业的大致参考标准。如果需要精确的数字，可能该功能不适合你。

鸣潮的声骸系统给了角色配置极大的自由空间。声骸的主词条较副词条往往有着更大决定作用，且主词条的选择多种多样，但一旦主词条决定，基本不再发生变化。

因此玩家在刷声骸时往往更专注于副词条的价值。助手的测评决定抛弃主词条，仅针对副词条进行测评。

声骸测评主要从两个方面入手：

  1. 声骸有效词条数量（词条评级）
  2. 有效词条当前值与最大值比值总分（词条数值评级）

一个完美的声骸必定有着高等级的词条和高等级的词条数值。

词条测评

以词条对角色的价值为依据，将词条分为四类：

  • 必要词条（Level.3）
    数量固定为 2，对角色最为重要，必刷。例如对于主输出，一般双爆均为其必要词条。

  • 重要词条（Level.2）
    数量不限，对角色的重要程度不足必要词条，测评会计算重要词条的数量。

  • 次要词条（Level.1）
    数量不限，测评会计算次要词条的数量。

  • 废弃词条（Level.0）
    数量不限，对角色的提升基本无影响（例如生命奶妈的攻击力），因此该词条对测评无影响。

注意

因为重要词条与次要词条区别不大，故当前逻辑中将二者视为一类，即对词条测评等级的影响一样。

词条评分等级有五类：

  • ACE（Level.5）
    五条词条等级均在次要以上，且有两个必要词条。

  • SSS（Level.4）
    四条词条等级均在次要以上，且有两个必要词条。

  • SS（Level.3）
    三条词条等级均在次要以上且有两个必要词条；或者有四条词条等级均在次要以上，且有一条必要词条。

  • S（Level.2）
    两条词条等级均为必要，或者一条必要词条和两条次要词条以上。

  • N（Level.1）
    上述均不满足的情况。

词条数值评级

计算每个词条与最大值的比值。词条数值等级有五类：

  • ACE（Level.5）
    各词条比值之和大于 3.5，且拥有两条必要词条。

  • SSS（Level.4）
    比值大于 2.8，且拥有两条必要词条。

  • SS（Level.3）
    比值大于 2.1 且有两条必要词条，或者比值大于 2.4 且有一条必要词条。

  • S（Level.2）
    比值大于 1.6 且有一条必要词条，或者有两条必要词条（比值 1.2）。

  • N（Level.1）
    上述均不满足的情况。

总体声骸评级

单个声骸的评级分为词条评级与词条数值评级两部分，总体评级取决于这两部分。

先看两个指标：

最大总分 = (最大词条 Level + 最大词条数值 Level) * 5 = 50
当前总分 = (当前词条 Level + 当前词条数值 Level) * 5

以上述标明的 Level 为基础，对每个声骸进行累加获得总分，与最大值 50 进行比较：

  • ACE：总分大于 45（5×9）
  • SSS：总分大于 35（5×7）
  • SS：总分大于 25（5×5）
  • S：总分大于 18（5×3+3）。考虑到 S 的获取难度，略微提升三个点
  • N：上述均不满足的情况

自定义

目前有两种方式修改词条权重。

方式一：直接修改默认文件

前往助手安装目录 /assets/data/zh_CN/weight/default，修改每个词条重要程度，格式如下：

{
  "roleName": "今汐",
  "subPropWeights": {
    "共鸣技能伤害加成": 2,
    "普攻伤害加成": 0,
    "暴击": 3,
    "攻击": 1,
    "重击伤害加成": 0,
    "生命百分比": 0,
    "生命": 0,
    "共鸣效率": 1,
    "共鸣解放伤害加成": 2,
    "防御百分比": 0,
    "暴击伤害": 3,
    "攻击百分比": 1,
    "防御": 0
  }
}

可按如下对应关系修改数字：

  • 必要词条：3
  • 重要词条：2
  • 次要词条：1
  • 废弃词条：0

请确保修改后格式正确，否则可能会造成程序错误。

方式二：使用 custom 目录（推荐）

同样前往助手安装目录 /assets/data/zh_CN/weight/default，将要修改的角色文件复制到 /assets/data/zh_CN/weight/custom，再修改每个词条重要程度。

推荐使用这种方式：方式一的数据可能会随着助手更新而被覆盖。
